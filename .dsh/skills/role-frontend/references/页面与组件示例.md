# 页面与组件示例

本例采用 Vue + TypeScript 展示页面级模块化。它是结构参考，不代表当前项目已有 Vue 页面；按任务项目的目录、框架和代码约定调整，不为套用示例迁移技术或目录。

## 目录结构

```text
login/
├─ index.vue
├─ types/
│  └─ index.ts
├─ utils/
│  └─ can-submit-credentials.ts
└─ components/
   ├─ layout.vue
   ├─ left.vue
   ├─ right.vue
   └─ form.vue
```

- `index.vue`：页面入口，持有登录状态，连接布局组件与登录服务。
- `layout.vue`：只负责左右区域的整体布局，组合 `left.vue` 和 `right.vue`。
- `left.vue`：展示 Logo、标题、描述和主视觉。
- `right.vue`：组织右侧标题与登录表单，将表单事件向上转发。
- `form.vue`：只负责账号密码输入、提交和表单反馈，不直接调用登录接口。
- `types/`：保存登录页多个组件共用的类型。
- `utils/`：保存登录页多个组件共用的工具逻辑。

每个组件都可以只在一个页面内使用。拆分依据是职责和独立变化边界，不要求先有复用。

## 共享类型与工具

`types/index.ts`：

```ts
export interface LoginCredentials {
  account: string;
  password: string;
}

export type LoginStatus = "idle" | "submitting" | "error";
```

`utils/can-submit-credentials.ts`：

```ts
import type { LoginCredentials } from "../types";

export function canSubmitCredentials(credentials: LoginCredentials): boolean {
  return credentials.account.trim().length > 0 && credentials.password.length > 0;
}
```

表单用该函数控制提交按钮，页面入口也用它阻止无效请求。两处共用同一规则，修改时只维护一份实现。单组件私有类型或函数留在组件内，不必提前放进共享目录。

## 页面入口

`index.vue`：

```vue
<script setup lang="ts">
import { ref } from "vue";
import LoginLayout from "./components/layout.vue";
import type { LoginCredentials, LoginStatus } from "./types";
import { canSubmitCredentials } from "./utils/can-submit-credentials";
// 使用项目现有登录服务和错误信息转换；导入路径按项目调整。
import { loginWithCredentials, toDisplayMessage } from "@/services/auth";

const status = ref<LoginStatus>("idle");
const errorMessage = ref("");

async function handleSubmit(credentials: LoginCredentials) {
  if (status.value === "submitting" || !canSubmitCredentials(credentials)) return;

  status.value = "submitting";
  errorMessage.value = "";
  try {
    await loginWithCredentials(credentials);
    // 按产品流程执行成功后的跳转或反馈。
  } catch (error) {
    status.value = "error";
    errorMessage.value = toDisplayMessage(error);
  } finally {
    if (status.value === "submitting") status.value = "idle";
  }
}
</script>

<template>
  <LoginLayout
    site-title="示例网站"
    description="一句简短的产品说明。"
    logo-src="/assets/logo.svg"
    hero-image-src="/assets/login-hero.jpg"
    :status="status"
    :error-message="errorMessage"
    @submit="handleSubmit"
  />
</template>
```

页面入口只连接页面状态、成功流程和现有服务，不实现左右布局或表单细节。示例中的标题、资源地址和服务导入均需替换成项目实际内容。

## 布局组件

`components/layout.vue`：

```vue
<script setup lang="ts">
import LoginLeft from "./left.vue";
import LoginRight from "./right.vue";
import type { LoginCredentials, LoginStatus } from "../types";

defineProps<{
  siteTitle: string;
  description: string;
  logoSrc: string;
  heroImageSrc: string;
  status: LoginStatus;
  errorMessage: string;
}>();

const emit = defineEmits<{
  (event: "submit", credentials: LoginCredentials): void;
}>();
</script>

<template>
  <main class="login-layout">
    <LoginLeft
      :site-title="siteTitle"
      :description="description"
      :logo-src="logoSrc"
      :hero-image-src="heroImageSrc"
    />
    <LoginRight :status="status" :error-message="errorMessage" @submit="emit('submit', $event)" />
  </main>
</template>

<style scoped>
.login-layout {
  display: grid;
  min-height: 100vh;
  grid-template-columns: minmax(0, 1fr) minmax(22rem, 1fr);
}

@media (max-width: 52rem) {
  .login-layout {
    grid-template-columns: minmax(0, 1fr);
  }
}
</style>
```

布局组件只安排区域，不承载登录请求或表单状态。Grid 负责桌面左右布局，小屏改为单列。

## 表单组件

`components/form.vue`：

```vue
<script setup lang="ts">
import { computed, ref } from "vue";
import { canSubmitCredentials } from "../utils/can-submit-credentials";
import type { LoginCredentials, LoginStatus } from "../types";

const props = defineProps<{
  status: LoginStatus;
  errorMessage: string;
}>();

const emit = defineEmits<{
  (event: "submit", credentials: LoginCredentials): void;
}>();

const account = ref("");
const password = ref("");
const canSubmit = computed(() =>
  canSubmitCredentials({
    account: account.value,
    password: password.value,
  }),
);

function submit() {
  emit("submit", {
    account: account.value.trim(),
    password: password.value,
  });
}
</script>

<template>
  <form class="login-form" @submit.prevent="submit">
    <label class="login-form__field">
      <span>账号</span>
      <input v-model="account" name="account" autocomplete="username" required />
    </label>

    <label class="login-form__field">
      <span>密码</span>
      <input
        v-model="password"
        name="password"
        type="password"
        autocomplete="current-password"
        required
      />
    </label>

    <p v-if="errorMessage" role="alert">{{ errorMessage }}</p>
    <button type="submit" :disabled="!canSubmit || props.status === 'submitting'">
      {{ props.status === "submitting" ? "正在登录…" : "登录" }}
    </button>
  </form>
</template>

<style scoped>
.login-form {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

.login-form__field {
  display: flex;
  min-width: 0;
  flex-direction: column;
  gap: 0.375rem;
}
</style>
```

表单维护输入值，通过类型化事件提交数据；不直接访问 API。账号有效性判断由页面域工具统一处理，避免表单和页面各写一套规则。实际表单字段、校验和文案按已确认需求调整。

## 从页面共享提升到全局

- 只被一个组件使用的逻辑留在组件内。
- 同一页面多个组件共用的类型和工具放在该页面的 `types/`、`utils/`。
- 确认其他页面也需要同一能力后，再把它提升到项目约定的全局共享目录，例如共享组件、类型或工具目录。
- 提升后只保留一份实现；各页面从共同出口引用，不复制代码各自维护。按项目的导出方式统一更新引用。
- 不因“以后可能复用”提前全局化；跨页面共享应有真实使用方和稳定职责。

例如，同一原则应用于目录页：

```text
directory/
├─ index.vue
├─ types/
├─ utils/
└─ components/
   ├─ layout.vue
   ├─ content.vue
   ├─ list.vue
   └─ detail.vue
```

`index.vue` 连接页面状态与 `layout.vue`；`content.vue` 组合 `list.vue` 和 `detail.vue`。目录页内共享类型和工具分别放在 `directory/types/`、`directory/utils/`。

## 组件边界

- 页面入口组合页面、业务流程和状态；布局组件组合区域；区域组件分别负责自己的视图或交互。
- 组件可以只使用一次；若区域有独立布局、状态、交互或变化边界，就可以拆分。
- 不是每个标签都要成为组件。拆分后应能明确组件职责及其 props、事件和 slots。
- 数据通过 props 向下传递，操作通过类型化事件向上通知；共享状态由合适的上层持有。
- Flex 适合一维排列，Grid 适合二维区域布局。断点、间距和视觉样式按项目设计系统调整。
- 示例中的名称、字段、路径、接口、图片、文字和样式均为占位内容，不构成产品需求或项目规范。
