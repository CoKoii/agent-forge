# 页面与组件示例

本文件提供开发参考，不要求每个页面采用相同结构。实际实现必须遵循仓库已有约定。

## 1. 页面开发检查清单

实现页面前确认：

- 对应的需求编号和验收标准。
- 页面路由和访问权限。
- 使用的 API 及其请求响应类型。
- 页面加载、空数据和错误状态。
- 用户操作及其成功、失败反馈。
- 是否已有可复用组件。

## 2. 组件设计示例

以设备列表为例，页面可以按职责拆分为：

- `DeviceListPage`：组织页面流程。
- `DeviceFilters`：接收筛选条件并发出筛选事件。
- `DeviceTable`：展示设备数据并触发用户操作。
- `DeviceStatusTag`：统一展示设备状态。
- `useDevices`：在符合项目约定时封装设备数据逻辑。

这些名称仅为示例。创建文件前先检查现有目录和命名约定。

## 3. 列表页面状态

| 状态     | 页面行为                         |
| -------- | -------------------------------- |
| 加载中   | 显示加载反馈                     |
| 有数据   | 显示列表                         |
| 无数据   | 显示空状态及适当的下一步操作     |
| 请求失败 | 显示错误信息，并在适用时允许重试 |
| 无权限   | 按项目权限策略提示或阻止访问     |

## 4. 提交表单

- 明确必填字段和输入规则。
- 在适当时机显示校验错误。
- 提交过程中防止重复操作。
- 根据真实接口结果显示成功或失败反馈。
- 请求失败时保留合理的用户输入。
- 不在前端单独承担必须由后端执行的安全校验。

## 5. 示例使用原则

- 示例用于统一实现思路，不代表项目必须采用示例中的文件结构。
- 优先检查已有组件和工具函数。
- 只有当示例适用于当前任务时才读取和使用。
- 如果示例与正式需求、架构或仓库约定冲突，以已批准的正式约定为准，并向总控 Agent 报告冲突。
