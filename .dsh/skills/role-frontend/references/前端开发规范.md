# 前端开发规范

## 1. 技术约定

- 使用 Vue 与 TypeScript。
- 优先遵循仓库中实际配置的 Vue 版本、构建工具和代码规范。
- 优先使用已有依赖，不随意增加第三方库。
- 使用 pnpm 管理依赖。
- 测试优先遵循项目已有的 Vitest 和 Playwright 配置。

## 2. 代码组织

- 页面负责组织页面结构与业务流程。
- 可复用 UI 逻辑优先抽取为组件或组合式函数。
- API 调用遵循项目已有的请求封装。
- 类型定义应清晰，避免重复定义相同的数据结构。
- 公共组件与业务专属组件应合理区分。
- 不为了抽象而抽象，简单逻辑不必强行拆分。

## 3. Vue 组件

- 使用清晰的组件名称和属性名称。
- 明确组件的输入、输出和事件。
- 避免直接修改父组件传入的属性。
- 正确处理组件生命周期和副作用。
- 避免不必要的重复渲染和复杂响应式依赖。
- 组件应保持职责单一、便于测试。

## 4. TypeScript

- 为重要的函数参数、返回值和业务数据定义类型。
- 优先使用明确的联合类型和类型收窄。
- 谨慎使用类型断言。
- 不使用 `any` 隐藏真实类型错误。
- 类型定义应与实际 API 契约一致。

## 5. 页面状态

根据功能需要处理：

- 加载中
- 成功
- 空数据
- 请求失败
- 表单校验失败
- 无权限
- 重复提交
- 操作成功反馈

不适用的状态不必强行添加。

## 6. 可访问性与响应式

- 表单字段应有明确标签。
- 交互元素应具有清晰的操作含义。
- 颜色不能作为唯一的信息表达方式。
- 合理处理键盘操作和焦点。
- 页面布局应适应项目支持的屏幕尺寸。

## 7. 测试

- 单元测试优先覆盖业务逻辑和边界条件。
- 组件测试关注渲染、交互和状态变化。
- Playwright 用于适合端到端验证的关键用户流程。
- 测试应验证真实行为，不应只检查实现细节。
- 执行前检查仓库现有测试脚本，不猜测命令。

## 8. 禁止事项

- 擅自更换 UI 框架或引入大型依赖。
- 将密钥写入前端代码。
- 通过删除测试掩盖缺陷。
- 忽略接口错误或将失败伪装为成功。
- 未经确认修改共享 API 契约。
