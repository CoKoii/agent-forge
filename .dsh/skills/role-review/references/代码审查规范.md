# 代码审查规范

## 1. 需求符合性

- 是否实现所有相关需求和验收标准。
- 是否遗漏异常流程、边界条件和权限场景。
- 是否存在未经需求授权的行为变更。
- 是否能追踪到对应的 `REQ-模块名-NNN` 或 `AC-模块名-NNN`。

## 2. 代码质量

- 逻辑是否正确，是否存在空值、类型或状态处理错误。
- 是否存在重复实现、过度耦合或不必要的复杂度。
- 是否遵循现有项目结构、命名和编码规范。
- 是否存在资源泄漏、竞态条件或错误处理缺失。

## 3. 安全性

- 是否正确执行身份认证与权限校验。
- 是否存在 SQL 注入、XSS、命令注入或不安全反序列化风险。
- 是否泄露密码、令牌、密钥或敏感信息。
- 是否正确校验和限制外部输入。
- 是否存在越权访问、批量赋值或敏感数据暴露。

## 4. API 与数据库

- API 请求、响应、状态码和错误结构是否符合契约。
- 修改是否破坏现有调用方的兼容性。
- 数据库迁移是否可执行，是否考虑已有数据。
- 是否存在事务缺失、数据一致性问题或低效查询。
- 是否正确处理索引、约束和并发更新。

## 5. 前端检查

- 是否覆盖加载、空数据、失败和无权限状态。
- 表单校验、路由权限和交互行为是否正确。
- 是否存在重复请求、状态不同步或内存泄漏。
- 是否考虑键盘操作和基本可访问性。
- 是否将敏感业务权限仅交由前端控制。

## 6. 后端检查

- 是否使用 DTO 或等效机制校验输入。
- 是否正确处理异常、事务和资源生命周期。
- 是否避免将内部异常和敏感信息返回给客户端。
- 是否验证用户对目标资源的访问权限。
- 是否存在 N+1 查询或不必要的全表扫描。

## 7. 测试检查

- 是否覆盖正常、异常、边界和权限场景。
- 测试是否对应相关验收标准。
- 是否存在仅断言执行成功、没有验证实际结果的测试。
- 是否遗漏回归测试。
- 测试失败是否被错误忽略或标记为通过。

## 8. Monorepo 影响

- 是否影响其他 workspace 包或应用。
- 是否更新相关类型、共享契约和调用方。
- 是否影响 pnpm 脚本、构建、测试或部署配置。
- 是否引入不必要的依赖或循环依赖。

## 9. 发现问题的要求

每个问题至少包含：

- 严重程度。
- 文件路径与行号。
- 可复现的事实或代码证据。
- 实际影响。
- 建议修复方向。

没有发现问题时，应说明实际审查范围及未执行的验证，不得保证绝对无缺陷。
