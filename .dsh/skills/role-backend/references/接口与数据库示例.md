# 接口与数据库示例

本文件仅提供设计参考。具体实现必须遵循项目现有架构、ORM 和 API 契约。

## 1. NestJS 模块职责示例

以用户管理功能为例：

- `UsersModule`：组织用户相关能力。
- `UsersController`：接收 HTTP 请求。
- `UsersService`：处理用户业务逻辑。
- DTO：定义和校验请求输入。
- 数据访问层：按照项目既有方式读写数据库。

以上是职责示例，不代表必须创建同名文件。先检查项目现有结构。

## 2. API 设计检查清单

实现接口前确认：

- 关联需求编号和验收标准。
- 请求方法及路径。
- 身份认证和资源权限。
- 请求参数及校验规则。
- 成功响应格式。
- 错误响应格式。
- 分页与排序规则（如适用）。
- 幂等性与并发要求（如适用）。
- 相关测试用例。

## 3. 数据库设计检查清单

新增或修改表时确认：

- 表的业务用途。
- 主键和字段类型。
- 必填字段及默认值。
- 唯一约束、外键和检查约束。
- 查询所需索引。
- 关联数据删除或更新策略。
- 现有数据迁移方案。
- 部署顺序和回滚风险。

## 4. 数据迁移原则

- 先确认项目现有迁移工具和命名规则。
- 不直接修改已经应用到环境中的历史迁移，除非项目规范明确允许。
- 避免未经评估的锁表和长时间数据迁移。
- 删除字段或收紧约束前，检查所有使用方及现有数据。
- 对高风险变更提供备份、恢复或分阶段发布方案。
- 不在未经授权的环境执行迁移。

## 5. 示例优先级

发生冲突时，按以下顺序处理：

1. 已批准的需求和验收标准。
2. 已批准的架构设计与 API 契约。
3. 仓库现有代码和正式项目规范。
4. 本文件中的示例。

如果上层规范存在冲突，暂停相关实现并报告总控 Agent。
