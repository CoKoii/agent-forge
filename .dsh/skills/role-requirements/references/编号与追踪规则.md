# 编号与追踪规则

## 编号

- 需求：`REQ-MODULE-NNN`
- 业务规则：`BR-MODULE-NNN`
- 验收标准：`AC-MODULE-NNN`
- 测试用例：`TC-MODULE-NNN`
- 变更记录：`CHG-YYYYMMDD-NNN`

`MODULE` 使用稳定的大写英文模块名。编号按类型和模块递增；新建前检查模块文件、索引或变更日志。已分配的编号永不复用。需求修改沿用原 ID，新增独立规则或标准才分配新 ID。

需求 Agent 负责分配 REQ、BR、AC 和 CHG；测试 Agent 负责分配 TC。不要让多个 Agent 同时编辑同一编号序列；有并行需求变更时由总控指定唯一记录负责人。

## 状态

需求状态：

- `待确认`：需求或关键规则仍待用户/授权决策者确认。
- `已批准`：范围和验收标准已确认，可以拆解实施。
- `已拒绝`：提案未获批准，保留原因和记录。
- `已废弃`：曾批准的需求不再适用，保留替代关系和原因。

实现状态放运行时任务板；测试状态只写在测试报告中。两者不能代替需求决策状态。

## 追踪

- 每条已批准需求至少有一个 AC。
- 每条 BR 关联一个或多个 REQ；每条 AC 关联所属 REQ。
- 每个 TC 关联一个或多个 AC。TC 由测试 Agent 建立后回填到需求记录或测试报告。
- 新增、修改、拒绝或废弃需求时，检查相关架构、任务、代码和测试影响。
- 未确认的产品行为不得写成已批准的规则或验收结果。
