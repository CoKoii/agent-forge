# 编号与追踪规则

## 编号

- 需求：`REQ-MODULE-NNN`
- 业务规则：`BR-MODULE-NNN`
- 验收标准：`AC-MODULE-NNN`
- 测试用例：`TC-MODULE-NNN`
- 变更记录：`CHG-YYYYMMDD-NNN`

`MODULE` 使用稳定的大写英文模块名。编号按类型和模块递增；新建前检查索引及相关模块文档，必要时查看相关变更记录。已分配编号永不复用。修改沿用原 ID，新增独立需求、规则或标准才分配新 ID。

需求 Agent 分配 REQ、BR、AC、CHG；测试 Agent 分配 TC。避免多个 Agent 同时编辑同一编号序列；并行变更由总控指定唯一记录负责人。

## 状态

需求状态只表示决策：

- `待确认`：需求或关键规则待用户/授权决策者确认。
- `已批准`：范围和验收标准已确认，可以拆解实施。
- `已拒绝`：提案未获批准，保留原因和记录。
- `已废弃`：曾批准的需求不再适用，保留替代关系和原因。

实现进度和阻塞原因记在运行时任务板；测试状态、结果和证据记在测试报告中，不得以其替代需求状态。

## 追踪

- 每条已批准需求至少有一个 AC。
- 每条 BR 关联一个或多个 REQ；每条 AC 归属一个 REQ。
- 每个 TC 关联一个或多个 AC。需求文档只维护 TC-ID 到 AC-ID 映射；测试步骤、文件、执行结果及证据放测试报告。
- 新增、修改、拒绝或废弃需求时，检查相关架构、任务、代码和测试影响。
- 未确认的产品行为不得写成已批准的规则或验收结果。
