# 项目需求管理说明

本目录保存项目正式需求，所有需求变更必须纳入 Git 版本管理。

## 目录说明

- `registry.md`：全部需求的索引。
- `modules/`：按业务模块保存需求。
- `changes/CHANGELOG.md`：需求变更历史。

## 新增需求

1. 检查现有需求，确认没有重复。
2. 在对应模块文件中添加需求。
3. 分配需求、业务规则和验收标准编号。
4. 更新 `registry.md`。
5. 在 `changes/CHANGELOG.md` 中记录变更。

## 修改需求

1. 保留原需求编号。
2. 记录变更原因和修改内容。
3. 检查相关业务规则、验收标准和测试用例。
4. 更新索引和变更历史。

## 注意事项

未经确认的需求标记为待确认。
不得删除历史需求或重复使用编号。
