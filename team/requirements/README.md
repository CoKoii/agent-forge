# 需求管理

本目录保存正式需求。修改纳入 Git，并保留已分配编号和变更历史。

## 文件

- `registry.md`：需求查找索引，不重复需求正文。
- `modules/<MODULE>.md`：按业务模块保存需求；无需求的模块不建空文件。
- `changes/CHANGELOG.md`：记录变更原因、决策和影响，不复制完整需求契约。

## 工作方式

1. 阅读 `../README.md`、本索引和目标需求所在模块；根据索引及关联 ID 读取必要的相关需求。
2. 不通读所有模块或完整变更历史。需要历史背景时按目标需求关联的 CHG 编号查看对应记录。
3. 确认边界、重复项、依赖和待决问题；不明确时先询问用户或总控 Agent。
4. 按 Skill 模板新增或更新正文，沿用原 ID，不复用已分配 ID；更新索引和变更日志。
5. 检查链接、编号、状态及 REQ-BR-AC-TC 关联，并向总控 Agent 汇报影响以更新任务板。

## 记录原则

- 需求状态只表示决策：`待确认`、`已批准`、`已拒绝`、`已废弃`。实现进度和阻塞原因记在任务板，测试执行状态、结果及证据记在测试报告。
- 需求摘要写目标和边界，业务规则写稳定约束，验收标准写可观察结果；避免同一契约在多个章节重复展开。
- AC 不写测试执行方法。需求正文仅保留 TC-ID 到 AC-ID 的映射；测试步骤、代码路径和实际执行结果由测试报告维护。
- 变更日志记录原因、决策及影响；Git diff 保留正文差异。
