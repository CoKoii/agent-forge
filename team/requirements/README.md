# 需求管理

本目录保存正式需求。修改应纳入 Git，并保留历史编号。

## 文件

- `registry.md`：需求查找索引，不重复需求正文。
- `modules/<MODULE>.md`：按业务模块保存需求；每个模块一个文件。
- `changes/CHANGELOG.md`：需求变更原因、决策和影响记录。

暂无正式需求的模块不必创建空文件。

## 新增或修改

1. 先读 `../README.md`、本目录索引和相关模块文件。
2. 确认需求边界、重复项、依赖和待决问题；不明确时先询问用户或总控 Agent。
3. 按 Skill 模板新增或更新需求，沿用已有 ID，不复用已废弃编号。
4. 更新 `registry.md` 和变更日志；检查所有链接与关联 ID。
5. 将新增或变更的影响交给总控 Agent，供其更新任务板和实施计划。

## 记录原则

- 状态只表示需求决策：`待确认`、`已批准`、`已拒绝`、`已废弃`。
- 优先级使用 `P0`（紧急）、`P1`（高）、`P2`（普通）、`P3`（低）。
- 实现进度和阻塞状态记在任务板；测试执行结果记在测试报告，不复制到需求索引。
- 业务规则和验收标准只在对应需求正文维护；测试用例由测试 Agent 编号并关联验收标准。
- 变更日志记录原因、决策与影响，不复制完整前后版本；Git 保留文本差异。
