# 团队工作区

本目录保存跨 Agent、跨任务需要持续维护的项目资料。所有正式资料以 Git 版本管理。

## 目录

- `requirements/`：需求正文、索引和变更记录。
- `architecture/`：系统设计、接口契约、数据模型和技术决策。
- `testing/plans/`：持久化测试计划。
- `testing/reports/`：测试执行报告。
- `reviews/`：独立审查报告。

按需创建子目录和文件，不要为简单任务生成空文档。

## 边界

- 运行中的负责人、依赖、状态和阻塞记录在运行时任务板，不在此复制一份。
- 源码与可执行测试留在项目现有目录；本目录只保存计划、契约和交付报告。
- 需求正文是需求事实源；索引只用于查找，测试状态以实际测试报告为准。
- 所有文档都应标明关联需求 ID；无需求 ID 的纯维护工作可写任务或范围名称。
